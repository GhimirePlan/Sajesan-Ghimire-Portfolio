# Search indexing

Canonical site: https://sajesanghimire.com.np/

- `/robots.txt` declares `/sitemap.xml` and prevents API crawling.
- `/sitemap.xml` reads published, non-archived articles and projects. It uses actual content modification dates and caches results for five minutes.
- Blog document requests are served through `server/routes/seoRoutes.js`: initial HTML contains article content, metadata, a canonical URL and BlogPosting structured data. The normal React application then handles interaction. HTML reads do not increment article views.
- Blog HTML caches for two minutes in a warm process and at the CDN, with stale-while-revalidate. Publishing changes can take several minutes to appear in cached search responses.
- The HTML renderer caches the static `/index.html` asset for its versioned JavaScript/CSS references. Keep that asset publicly available. It deliberately does not fetch a routed article URL.
- Home, project and article metadata update during client navigation through `useSeo`. Project filter variations canonicalize to `/projects`; individual project links have their own canonical query URL.
- Login and admin routes send `X-Robots-Tag: noindex, nofollow`. Do not disallow these routes in robots.txt: crawlers must be able to read their noindex headers.
- Draft and missing article URLs return HTTP 404 with noindex. Temporary article rendering failures return 503 and Retry-After rather than an indexable error page.

## Google Search Console

Verify ownership of the domain property using the DNS TXT record provided by Google, then submit `https://sajesanghimire.com.np/sitemap.xml`. Use URL Inspection to request indexing for the homepage and important articles. Verification values must come from the site's owner's Search Console account; they are not generated by this application. Search crawling, indexing, and ranking are controlled by Google.

## Checks

`npm run build` and `npm test --prefix server` verify the build and metadata sanitization/XML formatting. Set `TEST_MONGO_URI` to a disposable MongoDB instance for integration coverage of draft exclusion, sitemap responses, and initial article HTML. Integration tests create and remove their own randomly named databases.
